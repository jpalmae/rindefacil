Guía de Uso Completa

Esta guía explica cómo usar {{ brand_app_name }} de punta a punta: crear gastos, subir boletas, entender validaciones antifraude, armar rendiciones, operar flujos de aprobación, administrar la plataforma y usar API Keys.

1. Flujo recomendado (resumen)

  1. Ingresa a Nuevo Gasto.
  2. Permite acceso a GPS y verifica que quede capturada tu ubicación.
  3. Sube foto/PDF de boleta para autocompletado con IA.
  4. Revisa monto, comercio, fecha y hora de boleta.
  5. Completa el motivo (mínimo 15 caracteres) y guarda.
  6. Agrupa tus gastos en una rendición y envíala a aprobación.

2. Conceptos clave: gasto, rendición y aprobación

Gasto: es el comprobante individual. Cada boleta, ticket o factura se registra como un gasto separado.

Rendición: es la agrupación de uno o más gastos. Tiene título, descripción, total y estado propio.

Flujo de aprobación: no se ejecuta sobre el gasto individual. Se ejecuta cuando envías la rendición.

Secuencia correcta: primero creas gastos, después armas la rendición y recién entonces la envías a aprobación.

Importante: si no existe un flujo activo configurado para tu empresa, la rendición no se envía y se mantiene en borrador.

3. Crear un gasto correctamente

Ruta: Mis Gastos -> + Nuevo Gasto.

Campos obligatorios: monto, comercio, fecha, motivo y GPS activo.

Hora boleta: recomendable completarla siempre. Mejora la trazabilidad y la validación antifraude frente al momento real de rendición.

Boleta con IA: al cargar la imagen/PDF, el sistema intenta extraer monto, comercio, fecha y hora automáticamente.

4. Cómo funciona la validación antifraude

Cada gasto obtiene una validación Coherente, Parcial o Riesgo. Se calcula con:

  • Coincidencia entre comercio y dirección GPS capturada.
  • Coincidencia entre fecha de boleta y fecha de rendición.
  • Coincidencia entre hora de boleta y hora de rendición (margen de 20 minutos).
  • Rango horario habitual: lunes a viernes entre 09:00 y 19:00.

Regla especial: si el gasto cae en fin de semana o fuera de horario hábil, la validación no queda en “Coherente” (baja al menos a “Parcial”).

5. Crear y enviar una rendición

Ruta: Rendiciones -> Nueva Rendición.

Selecciona gastos en borrador, define título/descripción y crea la rendición.

Tipo de rendición: debes indicar si la rendición es para Solicitar devolucion o si corresponde a Tarjeta corporativa.

Las rendiciones de tarjeta corporativa siguen el mismo flujo de revisión, pero no implican pago al empleado.

Al crearla, la rendición aún no está aprobada ni enviada. Queda en borrador.

Cuando esté lista, usa Enviar Rendición. En ese momento el sistema busca el flujo aplicable y la deriva a revisión.

Si no existe un flujo activo, la rendición no se envía y debes esperar a que administración configure uno.

Si un aprobador necesita respaldo adicional, puede dejar la rendición en estado Antecedentes solicitados con una explicación clara del faltante.

En ese caso verás un bloque destacado con el motivo y un botón Reenviar Antecedentes para responder y retomar el mismo paso del flujo.

6. Roles y perfiles

El acceso a menús y acciones depende del rol asignado al usuario.

Rol Capacidades principales
Employee Crear gastos, crear/enviar rendiciones propias, ver estado y observaciones.
Manager Revisar y aprobar/rechazar rendiciones según flujo, visibilidad ampliada de equipo.
Approver / Reviewer Participar como aprobador en pasos configurados por rol o por usuario.
Admin / Superadmin Administración completa: usuarios, centros de costo, flujos, branding y auditoría.

7. Flujos de aprobación

Ruta: Admin -> Flujos.

Cada flujo puede activarse según reglas (por ejemplo monto mínimo) y se compone de pasos secuenciales.

El sistema evalúa el flujo cuando el usuario envía la rendición. Si hay varios flujos, selecciona el primero que cumpla la regla configurada.

Tipos de aprobador por paso:

  • role: aprueba un rol específico (ej: manager, admin).
  • user: aprueba un usuario específico.
  • manager: aprueba el jefe directo del solicitante.

Al enviar una rendición, el sistema selecciona el flujo aplicable, mueve la rendición a revisión y notifica al aprobador del paso actual.

8. Administración (Admin/Superadmin)

Ruta: Admin.

  • Usuarios: alta, edición, eliminación, asignación de rol, manager y centro de costo.
  • Centros de costo: creación/edición con código y presupuesto.
  • Flujos: diseño del pipeline de aprobación por pasos.
  • Branding: nombre de app, ícono, logo y dominio por defecto de usuarios.
  • Auditoría: trazabilidad de acciones administrativas y operativas.

Antes de habilitar usuarios finales, conviene configurar al menos un flujo de aprobación. Sin flujo, las rendiciones no se enviarán.

9. Estados y alertas

  • Borrador: gasto creado, aún no enviado en rendición.
  • Enviado: está dentro de una rendición en proceso de aprobación.
  • Antecedentes solicitados: un aprobador pidió mayor información o complemento de la rendición. Debes revisar el motivo, responder y reenviar.
  • Aprobado / Rechazado: resultado del flujo.
  • Advertencias: pueden aparecer por duplicados, políticas o score antifraude.

Diferencia importante: un gasto puede estar en borrador aunque la rendición todavía no exista. La aprobación siempre se ve en la rendición.

10. API Keys para agentes IA

Ruta: Mi Perfil -> API Keys para Agentes IA.

Cada usuario puede generar claves personales que heredan sus permisos para integrar Telegram, WhatsApp u otros agentes.

En API, para crear gastos también se debe enviar ubicación GPS (gps_latitude y gps_longitude).

Formato recomendado de fecha por API: DD/MM/YYYY.

11. Buenas prácticas para evitar rechazos

  • Rinde apenas ocurre el gasto (mejor score y mejor trazabilidad).
  • No edites manualmente comercio/fecha/hora si la boleta ya fue leída correctamente.
  • Sube imágenes nítidas, completas y sin cortes.
  • Describe claramente el motivo y su contexto de negocio.
